## About

The xPaint Project.

xPaint is an multipurpose editor, that has scriptable sprites,
and uses the PaintPower-VM to run code.

PaintScript is a simple dynamic programming language made as
the default language of the PaintPower-VM.

The goal of PaintScript is to ease the
transition from Scratch (GUI based) to Text based programming.
It has syntax similar to JavaScript, has simple instructions, and is
made by someone who had JavaScript as their first real programming language.

Just like Scratch, the code targets one sprite.
You can have multiple scripts that can talk to each other, but they must target the same sprite.

Similar to Adobe Flash, an instance same must be set for the sprite, that way the sprite itself can
be named whatever while still being referenced safely in the code.

At the top of the file, it must be declared what sprite this script is for.
It must be in the first line.

example:

```text

#Sprite Sprite_1

```

A sprite can be named "Sprite 1" in the editor while being
referenced as "Sprite_1" in the code.

"Why can't a sprite be named the same as in the editor itself?"

Well simple, when the Code Reader reads our code it looks for special words called "keywords", or
special characters like

```text
@, +, -, *, /, ',', "'", '"', ., #, {, }, (, ), [, ], ' '.
```

A keyword is separated by either a space, or a special character.

Some keywords are built in, and have built in features. While some can be created by you!
Custom keywords are called Functions and Variables, but you will learn that later.

Anyway, because of the separation of keywords,
we must have a code-safe name for our Sprites, instead of "Sprite 1" -> "Sprite_1".

Well, why not "Sprite-1"?

Well because '-' is a special character,

so the Code Reader reads it as "Sprite - 1", which is basically: "Sprite SUBTRACT 1".
and that's not what we want, '_' is a safe character, so we will use it instead.

"Sprite_1"

Now let's start coding!

## Events

### Start event

Similar to the "On Greenflag clicked" block, we have the "@Start" event.

We write it like this:

```text

@Start {}

```

What is this? Let's break it down!

The '@' symbol represents an event, the text after is the name of the
event, so it's the "Start" event, this is the same as the green flag event in Scratch.

And for those curly braces "{}", we put our code in between them.
That's how we know where the code starts and ends inside of this event handler.

By the way what we wrote "@Start {}" is called an event handler. Because we do something when that event is
activated. We can have multiple event handlers, we can also have multiple handlers for the same event.

Now why don't we make your first program!

Here is a simple program written in PaintScript.
 
```text
#Sprite Sprite_1

@Start {
	say("Hello, World! :)");
	call @Refresh;
}
```

We now have a "Hello world" program! Link this as the main Script
in the "Sprite Properties" panel, then click "Build and Run".

(If you are not using the editor and are coding in PaintScript directly, use "log" instead of "say".)

You should now see your sprite saying "Hello, World! :)"!

### Messages

Ok, let's learn about a new handler now. If you learned Scratch before, then you would know about
"messages". "Messages" allow us to start a new event of our own.

In Scratch, a message must be created, in PaintScript, you can just start writing handlers.

```text

@Message1 {}

```

Oops! That won't work! Why?

Well simple, when the Code Reader reads our code it looks for special words called "keywords" or special characters
like '@'. A keyword is separated by either a space, or a special character.

In this case, the '@' means an event, so the code reader looks for
an event that is built into PaintScript itself, not a custom event. 
So when it sees "@Message1" it freaks out because it was not ready for that.

So in PaintScript, you can not create a custom event directly, that's why we have messages.
A message is not just an event directly either, it has a special handler for you.

The "@receive" handler is a built in message handler that is activated whenever a message is broadcasted.

```text

@receive {}

```

Let's break this down.

Whenever ANY message is broadcast, this handler runs.

